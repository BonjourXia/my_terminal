第 1 步：编译（在电脑上）
----------------------------------------------------------------
    cd /home/book/Desktop/xiangmu/smart_terminal-main/smart_terminal-main/my_terminal/build-arm
    make -j$(nproc)

    ◆ 什么时候"只要 make"：改了 .cpp / .h 的内容。make 会自动只重编改过的文件
    ◆ 什么时候"要先重新 qmake"：
        · 新增/删除了源文件
        · 改了 .pro / .pri 里的 SOURCES += / HEADERS += / QT += / LIBS +=
      重新 qmake 的命令：
        MY_TERMINAL_BOARD=1 \
        /home/book/100ask_imx6ull-sdk/Buildroot_2020.02.x/output/host/bin/qmake ../my_terminal.pro

      ⚠ MY_TERMINAL_BOARD=1 这个开关不能忘：它是 .pro 里"编 ARM 版还是 x86 版"的开关。
        跑完看输出，出现 "=== 构建目标：ARM 板 ===" 才对。
        忘了它 → 编出来是电脑上跑的 x86 程序，推到板子上跑不了。
      ⚠ 别手动加 -spec 参数，buildroot 的 qmake 有自己的默认 spec，加了反而报错。

    ◆ 编完验证一句（重要）：
        file my_terminal
        正确 = "ELF 32-bit LSB ... ARM ... interpreter /lib/ld-linux-armhf.so.3"
        错误 = "ELF 64-bit ... x86-64"  → 回上一步，检查 qmake 的环境变量

    ◆ 编译报错的常见原因：
        · 少分号 / 拼错名字 → 看报错的行号
        · 新加的 .cpp 没写进 .pro 的 SOURCES += → 链接时报 undefined reference to ...
        · 改了头文件里的类声明忘了保存 → 先存盘再编

第 2 步：推到板子上（在电脑上）
----------------------------------------------------------------
    cd /home/book/Desktop/xiangmu/smart_terminal-main/smart_terminal-main/my_terminal/build-arm
    adb push my_terminal /root/my_terminal/

    成功输出类似：my_terminal: 1 file pushed ...
    · 第 0 级只需要推这一个文件（样式表 qss 已经编进二进制里了）
    · 以后级别要读图片/音乐/模型的，那些数据文件才需要另外推
      （第 1.1 级轮播图那 5 张 jpg 不用推：已经用 res.qrc 打进二进制里了）
    · 板子上还有一个 run.sh，是启动脚本（第 4 步要用到）。它不随编译变化，
      只有想改启动参数时才需要重推一次：
        adb push run.sh /root/my_terminal/ && adb shell "chmod +x /root/my_terminal/run.sh"
      板上那份改坏了，照文末【附录】重建即可
    · 想确认推成功：比对校验和
        电脑：md5sum my_terminal
        板子：adb shell "md5sum /root/my_terminal/my_terminal"
      两串一样就说明推过去的和电脑上的是同一个文件

第 3 步：杀掉旧进程（在电脑上）
----------------------------------------------------------------
    adb shell "killall my_terminal"     # 上一次没退干净的自己

第 4 步：运行（在电脑上，三种方式按需选）
----------------------------------------------------------------
【方式 A：一条命令遥控（日常推荐，报错直接回显在电脑上）】

    adb shell "cd /root/my_terminal && \
      QT_QPA_PLATFORM=linuxfb QT_QPA_FB_NO_LIBINPUT=1 QT_QPA_FB_TSLIB=1 \
      TSLIB_TSDEVICE=/dev/input/event1 TSLIB_CONFFILE=/etc/ts.conf \
      TSLIB_PLUGINDIR=/usr/lib/ts TSLIB_CALIBFILE=/etc/pointercal \
      TSLIB_FBDEVICE=/dev/fb0 XDG_RUNTIME_DIR=/tmp/runtime-root \
      ./my_terminal"
    退出：Ctrl+C

    等价简写（板子上已经放好这个脚本了）：
      adb shell "sh /root/my_terminal/run.sh"
      —— 它把"杀 mxapp2 + 杀自己 + 设那一串环境变量 + 启动"全打包好了，
         脚本内容见文末【附录】。想临时改某个环境变量时，再用上面写全的那条。

【方式 B：进板子里手动跑】

    adb shell                    # 在电脑上敲这一条，进入板子（提示符会变）
      cd /root/my_terminal
      QT_QPA_PLATFORM=linuxfb QT_QPA_FB_NO_LIBINPUT=1 QT_QPA_FB_TSLIB=1 \
      TSLIB_TSDEVICE=/dev/input/event1 TSLIB_CONFFILE=/etc/ts.conf \
      TSLIB_PLUGINDIR=/usr/lib/ts TSLIB_CALIBFILE=/etc/pointercal \
      TSLIB_FBDEVICE=/dev/fb0 XDG_RUNTIME_DIR=/tmp/runtime-root \
      ./my_terminal
    ⚠ 进了板子之后，命令前面【不要】再加 adb shell —— 板子上的 adb
      是用来当 USB 设备用的，在板子里敲它只会得到 error: closed

【方式 C：后台常驻（关掉终端也不停）】

    adb shell "start-stop-daemon -S -b -x /bin/sh -- -c '/root/my_terminal/run.sh >/tmp/myterm.log 2>&1'"

    看日志：adb shell "cat /tmp/myterm.log"
    停掉它：adb shell "killall my_terminal"
    查它在不在：adb shell "ps | grep my_terminal"

    ⚠ 为什么不能写成 "命令 &"（2026-10-13 实测，之前这页写的 setsid 写法是错的）：
      经 adb 启动的进程，adb shell 一退出就会被连坐杀掉 —— 写 "... &" 甚至
      加 setsid，都是"有时活有时死"（撞运气），典型现象是：
      命令看着执行成功了，但 ps 里没有、日志文件也没生成。
      正确做法是让进程"交给 init 接管"：start-stop-daemon -b 会双 fork，
      进程的爹变成 init，之后就与 adb 断不断线无关了。
      （-S=启动 -b=后台 -x 后面跟要跑的程序，-- 后面是传给它的参数）

【那串环境变量到底是干嘛的（背不下来就照抄）】

    QT_QPA_PLATFORM=linuxfb        直接往 /dev/fb0 帧缓冲上画（板子没有 X11/桌面）
    QT_QPA_FB_NO_LIBINPUT=1        别用 libinput 那套去找输入设备
    QT_QPA_FB_TSLIB=1              触摸改从 tslib 拿 ← 触摸能不能用的关键开关
    TSLIB_TSDEVICE                 触摸设备节点（板子上是 /dev/input/event1）
    TSLIB_CONFFILE                  tslib 的配置文件
    TSLIB_PLUGINDIR                 tslib 的插件目录
    TSLIB_CALIBFILE                触摸校准数据文件
    TSLIB_FBDEVICE                 告诉 tslib 画到哪个帧缓冲
    XDG_RUNTIME_DIR                Qt 要的一个运行时目录，不给会刷警告（不影响运行）

    记忆要点：少了 TSLIB 那两个开关，现象就是"界面显示正常、点屏幕没反应"

出问题：对号入座
----------------------------------------------------------------
    现象                            原因 / 药
    adb devices 空白                USB 掉线：重新插线；或 adb kill-server && adb devices
    屏幕全黑 / 还是 Snake 画面      mxapp2 没杀掉：adb shell "killall mxapp2"
    界面正常但触摸没反应            环境变量漏了（重点查 QT_QPA_FB_TSLIB / NO_LIBINPUT）
    error: closed                   你把 adb shell 敲进了板子里面
                                    先退回电脑提示符（book@100ask:...$）再敲
    file 显示 x86-64                qmake 时忘了 MY_TERMINAL_BOARD=1，回第 1 步重来
    ./my_terminal: not found        cd 错目录，或者第 2 步 push 没成功
    程序秒退、没有任何输出          用前台方式（A/B）跑，报错会打在终端上
    后台起了但 ps 里没有            方式 C 没写对：不能写 "命令 &"，
                                    要用 start-stop-daemon -b（详见方式 C 的说明）
    板子上时间显示 1970 年           板子没有 RTC 电池，正常现象。时间戳不能用来
                                    判断文件新旧 —— 要比版本就比 md5
    链接报 undefined reference      新加的源文件没写进 .pro 的 SOURCES +=
    Could not find qmake spec       qmake 命令行里手动加了 -spec，去掉

附录：板子上 /root/my_terminal/run.sh 的内容（改坏了照这个重建）
----------------------------------------------------------------
    #!/bin/sh
    killall mxapp2 2>/dev/null
    killall my_terminal 2>/dev/null
    sleep 1
    mkdir -p /tmp/runtime-root
    chmod 700 /tmp/runtime-root
    cd /root/my_terminal || exit 1
    QT_QPA_PLATFORM=linuxfb \
    QT_QPA_FB_NO_LIBINPUT=1 \
    QT_QPA_FB_TSLIB=1 \
    TSLIB_TSDEVICE=/dev/input/event1 \
    TSLIB_CONFFILE=/etc/ts.conf \
    TSLIB_PLUGINDIR=/usr/lib/ts \
    TSLIB_CALIBFILE=/etc/pointercal \
    TSLIB_FBDEVICE=/dev/fb0 \
    XDG_RUNTIME_DIR=/tmp/runtime-root \
    exec ./my_terminal

    · 前面几行是"干活前的准备"：杀掉出厂 Snake、杀掉上次的自己、备好 Qt 要的目录
    · 最后 exec ./my_terminal：exec 表示"用这个程序替换掉脚本本身"，
      所以进程就是 my_terminal 自己（ps 里看到的是 ./my_terminal，没有多余的 sh）
    · 改完记得 adb shell "chmod +x /root/my_terminal/run.sh"
