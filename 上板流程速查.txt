----------------------------------------------------------------
第 0.5 步：让板子上网（要跑"网络定位"这种联网页面才做）
----------------------------------------------------------------
    ⚠ 板子上的 WiFi【不是】开机自动连的，断电之后得重做一遍下面四步。
      两个原因：① 开机脚本 /etc/init.d/S09modload 里根本没有 8723bu；
                ② 配置文件放在 /tmp，而 /tmp 是内存盘，重启就清空。

    ① 加载 WiFi 模块
        adb shell "insmod /lib/modules/4.9.88/extra/8723bu.ko"
        · 路径必须写全，不能写 modprobe 8723bu —— 这个 .ko 不在 modules.dep
          里，modprobe 只会报 module not found，然后你就以为"网卡坏了"
        · 敲完这一刻才会冒出 wlan0（在此之前 ifconfig -a 里没这块网卡）
        · 重复敲会报 "File exists" —— 那说明模块早加载过了，不是故障，接着走 ②

    ② 写连网配置（热点名 sta / 密码 88888888）
        adb shell "cat > /tmp/wpa.conf <<'EOF'
        ctrl_interface=/tmp/wpa_supplicant
        update_config=1
        network={
        	ssid=\"sta\"
        	psk=\"88888888\"
        }
        EOF"
        · ssid/psk 那两行前面是一个【Tab】；带着文档的缩进整段照抄也照样能连
          （这条命令连同缩进都实测过，直接复制粘贴即可）
        · 换热点就改这两个引号里的内容

    ③ 连上热点
        adb shell "wpa_supplicant -B -i wlan0 -c /tmp/wpa.conf -D wext"
        · -B = 挂到后台跑；-D wext = 用老的 wext 后端
        · -D wext 不能省：板子上这个 rtl8723 驱动不会通过 cfg80211 上报
          "已经连上了"（内核日志那句 rtw_cfg80211_indicate_connect(wlan0)
          BSS not found !!），用默认的 nl80211 后端会卡死在认证之后 ——
          进程看着在跑、其实永远连不上
        · 敲完不会立刻连上：要扫一遍信道，实测 6 秒时还停在 SCANNING、
          十几秒才变成 COMPLETED —— 别急着判定失败，等 20 秒再敲下面验证那三句

    ④ 拿 IP 地址（前三步只是"链路连上"，这一步才给你 IP + 默认路由）
        adb shell "udhcpc -i wlan0 -n -q -t 8 -T 3"
        · 成功会打印 "lease of 10.239.x.x obtained" 和 "adding dns ..."
        · -n 没拿到就退出（此时会失败退出，别当它成功了）
        · -q 拿到就退出、不在后台常驻续租；租期实测 1 小时（3600 秒），
          板子连开超过 1 小时网自己掉了，把本步重跑一遍就行
        · ⚠ 这一步还管着"默认路由"，所以【重连之后必须重跑】：
          只跑 ③ 不跑 ④ 的典型症状 = ifconfig 看着有 IP、ping 却报
          Network is unreachable（route -n 里只剩 10.239.x.0 那条子网路由，
          没有 0.0.0.0 那条默认路由）

    ◆ 验证三句（从"有没有网卡"逐级看下来）：
        adb shell "ifconfig wlan0"                          看 inet addr 那行有没有地址
        adb shell "wpa_cli -p /tmp/wpa_supplicant status"   看 wpa_state=COMPLETED
        adb shell "ping -c 3 223.5.5.5"                     真通了才会 0% packet loss
      ⚠ wpa_cli 必须带 -p /tmp/wpa_supplicant：它默认去 /var/run/wpa_supplicant
        找控制口，而我们的配置把控制口放在 /tmp 了 —— 不带 -p 只会输出一片空白，
        看着像"没连上"，其实是没找对地方

    ◆ 和程序的先后顺序：
        先联网、再启动 my_terminal（第 4 步）。
        要是先启动了程序才想起联网：进"网络定位"页会停在"网络不通"，
        等网通了点一下页面里的【刷新】按钮就好，不用重启程序。

    ◆ 地图瓦片走的是 https，板子上还欠一份根证书：
        /etc/ssl/certs 出厂是空的 → IP 定位照样能用（那个接口是 http），
        但高德地图会拉不回来、页面上一片空白。这份证书已经装好了，
        重刷根文件系统后要再装一次，方法见文末【附录 3】。

    ◆ 嫌四步烦：板子上已经建好这个脚本了（/root/wifi.sh，内容见【附录 2】），
      以后每次开机只要一句 adb shell "sh /root/wifi.sh"。

第 1 步：编译（在电脑上）
----------------------------------------------------------------
    cd /home/book/Desktop/xiangmu/smart_terminal-main/smart_terminal-main/my_terminal/build-arm
    make -j$(nproc)

    ◆ 什么时候"只要 make"：改了 .cpp / .h 的内容。make 会自动只重编改过的文件
    ◆ 什么时候"要先重新 qmake"：
        · 新增/删除了源文件
        · 改了 .pro / .pri 里的 SOURCES += / HEADERS += / QT += / LIBS +=
      重新 qmake 的命令：
        MY_TERMINAL_BOARD=1 \
        /home/book/100ask_imx6ull-sdk/Buildroot_2020.02.x/output/host/bin/qmake ../my_terminal.pro

      ⚠ MY_TERMINAL_BOARD=1 这个开关不能忘：它是 .pro 里"编 ARM 版还是 x86 版"的开关。
        跑完看输出，出现 "=== 构建目标：ARM 板 ===" 才对。
        忘了它 → 编出来是电脑上跑的 x86 程序，推到板子上跑不了。
      ⚠ 别手动加 -spec 参数，buildroot 的 qmake 有自己的默认 spec，加了反而报错。

    ◆ 编完验证一句（重要）：
        file my_terminal
        正确 = "ELF 32-bit LSB ... ARM ... interpreter /lib/ld-linux-armhf.so.3"
        错误 = "ELF 64-bit ... x86-64"  → 回上一步，检查 qmake 的环境变量

    ◆ 编译报错的常见原因：
        · 少分号 / 拼错名字 → 看报错的行号
        · 新加的 .cpp 没写进 .pro 的 SOURCES += → 链接时报 undefined reference to ...
        · 改了头文件里的类声明忘了保存 → 先存盘再编

第 4 步：运行（在电脑上，三种方式按需选）
----------------------------------------------------------------
【方式 A：一条命令遥控（日常推荐，报错直接回显在电脑上）】

    adb shell "cd /root/my_terminal && \
      QT_QPA_PLATFORM=linuxfb QT_QPA_FB_NO_LIBINPUT=1 QT_QPA_FB_TSLIB=1 \
      TSLIB_TSDEVICE=/dev/input/event1 TSLIB_CONFFILE=/etc/ts.conf \
      TSLIB_PLUGINDIR=/usr/lib/ts TSLIB_CALIBFILE=/etc/pointercal \
      TSLIB_FBDEVICE=/dev/fb0 XDG_RUNTIME_DIR=/tmp/runtime-root \
      ./my_terminal"
    退出：Ctrl+C

    等价简写（板子上已经放好这个脚本了）：
      adb shell "sh /root/my_terminal/run.sh"
      —— 它把"杀 mxapp2 + 杀自己 + 设那一串环境变量 + 启动"全打包好了，
         脚本内容见文末【附录】。想临时改某个环境变量时，再用上面写全的那条。

【方式 B：进板子里手动跑】

    adb shell                    # 在电脑上敲这一条，进入板子（提示符会变）
      cd /root/my_terminal
      QT_QPA_PLATFORM=linuxfb QT_QPA_FB_NO_LIBINPUT=1 QT_QPA_FB_TSLIB=1 \
      TSLIB_TSDEVICE=/dev/input/event1 TSLIB_CONFFILE=/etc/ts.conf \
      TSLIB_PLUGINDIR=/usr/lib/ts TSLIB_CALIBFILE=/etc/pointercal \
      TSLIB_FBDEVICE=/dev/fb0 XDG_RUNTIME_DIR=/tmp/runtime-root \
      ./my_terminal
    ⚠ 进了板子之后，命令前面【不要】再加 adb shell —— 板子上的 adb
      是用来当 USB 设备用的，在板子里敲它只会得到 error: closed

【方式 C：后台常驻（关掉终端也不停）】

    adb shell "start-stop-daemon -S -b -x /bin/sh -- -c '/root/my_terminal/run.sh >/tmp/myterm.log 2>&1'"

    看日志：adb shell "cat /tmp/myterm.log"
    停掉它：adb shell "killall my_terminal"
    查它在不在：adb shell "ps | grep my_terminal"

    ⚠ 为什么不能写成 "命令 &"（2026-10-13 实测，之前这页写的 setsid 写法是错的）：
      经 adb 启动的进程，adb shell 一退出就会被连坐杀掉 —— 写 "... &" 甚至
      加 setsid，都是"有时活有时死"（撞运气），典型现象是：
      命令看着执行成功了，但 ps 里没有、日志文件也没生成。
      正确做法是让进程"交给 init 接管"：start-stop-daemon -b 会双 fork，
      进程的爹变成 init，之后就与 adb 断不断线无关了。
      （-S=启动 -b=后台 -x 后面跟要跑的程序，-- 后面是传给它的参数）

【那串环境变量到底是干嘛的（背不下来就照抄）】

    QT_QPA_PLATFORM=linuxfb        直接往 /dev/fb0 帧缓冲上画（板子没有 X11/桌面）
    QT_QPA_FB_NO_LIBINPUT=1        别用 libinput 那套去找输入设备
    QT_QPA_FB_TSLIB=1              触摸改从 tslib 拿 ← 触摸能不能用的关键开关
    TSLIB_TSDEVICE                 触摸设备节点（板子上是 /dev/input/event1）
    TSLIB_CONFFILE                  tslib 的配置文件
    TSLIB_PLUGINDIR                 tslib 的插件目录
    TSLIB_CALIBFILE                触摸校准数据文件
    TSLIB_FBDEVICE                 告诉 tslib 画到哪个帧缓冲
    XDG_RUNTIME_DIR                Qt 要的一个运行时目录，不给会刷警告（不影响运行）

    记忆要点：少了 TSLIB 那两个开关，现象就是"界面显示正常、点屏幕没反应"

附录 1：板子上 /root/my_terminal/run.sh 的内容（改坏了照这个重建）
----------------------------------------------------------------
    #!/bin/sh
    killall mxapp2 2>/dev/null
    killall my_terminal 2>/dev/null
    sleep 1
    mkdir -p /tmp/runtime-root
    chmod 700 /tmp/runtime-root
    cd /root/my_terminal || exit 1
    QT_QPA_PLATFORM=linuxfb \
    QT_QPA_FB_NO_LIBINPUT=1 \
    QT_QPA_FB_TSLIB=1 \
    TSLIB_TSDEVICE=/dev/input/event1 \
    TSLIB_CONFFILE=/etc/ts.conf \
    TSLIB_PLUGINDIR=/usr/lib/ts \
    TSLIB_CALIBFILE=/etc/pointercal \
    TSLIB_FBDEVICE=/dev/fb0 \
    XDG_RUNTIME_DIR=/tmp/runtime-root \
    exec ./my_terminal

    · 前面几行是"干活前的准备"：杀掉出厂 Snake、杀掉上次的自己、备好 Qt 要的目录
    · 最后 exec ./my_terminal：exec 表示"用这个程序替换掉脚本本身"，
      所以进程就是 my_terminal 自己（ps 里看到的是 ./my_terminal，没有多余的 sh）
    · 改完记得 adb shell "chmod +x /root/my_terminal/run.sh"

附录 2：板子上 /root/wifi.sh 的内容（已经建好了，改坏了照这个重建）
----------------------------------------------------------------
    板子上已经放好这个脚本了（/root/wifi.sh，chmod +x 过），
    所以第 0.5 步那四步，日常只要跑一句：

    电脑上的项目里也留了一份副本：my_terminal/wifi.sh
    板子重刷之后推一次即可：
        cd /home/book/Desktop/xiangmu/smart_terminal-main/smart_terminal-main/my_terminal
        adb push wifi.sh /root/wifi.sh && adb shell "chmod +x /root/wifi.sh"

    脚本内容（下面这份和板子上那份一模一样）：
    #!/bin/sh
    # 板子上网：加载网卡 → 写配置 → 连热点 → 拿 IP。板子每次开机跑一遍。
    # 用法（在电脑上）：adb shell "sh /root/wifi.sh"
    # 板子上坏了就照《上板流程速查.txt》附录 2 重建，或重新推一次本文件。

    killall wpa_supplicant 2>/dev/null      # 重复跑本脚本时，先清掉上一次的
    sleep 1
    grep -q '^8723bu' /proc/modules || insmod /lib/modules/4.9.88/extra/8723bu.ko

    # 下面到 EOF 之间的内容建议顶格写：heredoc 里的缩进会原样写进配置文件
    # （实测带着缩进 wpa_supplicant 也认，但顶格最保险）
    cat > /tmp/wpa.conf <<'EOF'
    ctrl_interface=/tmp/wpa_supplicant
    update_config=1
    network={
    	ssid="sta"
    	psk="88888888"
    }
    EOF
    wpa_supplicant -B -i wlan0 -c /tmp/wpa.conf -D wext
    udhcpc -i wlan0 -n -q -t 8 -T 3 || echo "!! 没拿到 IP —— 查 wpa_cli -p /tmp/wpa_supplicant status"
    ifconfig wlan0 | grep "inet addr"

    · 上面为了跟文档对齐，脚本内容都缩进了 4 格 —— 真写在板子上时去掉缩进；
      尤其是 cat 到 EOF 之间那几行，缩进会原样进配置文件（顶着写最保险）
    · 这份脚本在板子上实跑过（就是从 /root/wifi.sh 跑的）：网已经连着的时候
      再跑一遍，它会把旧的 wpa_supplicant 清掉重连、并且重新拿到默认路由，
      全程不用你插手 —— 哪天网掉了，第一反应就是重跑这一句
    · 跑的时候会刷几行吓人的警告，都是正常的，无视：
        rfkill: Cannot open RFKILL control device
        ioctl[SIOCSIWAP]: Operation not permitted
        ioctl[SIOCSIWENCODEEXT]: Invalid argument
      —— 用 wext 后端就会有这些；判断成败只看最后那行 inet addr（或再 ping 一下）
    · 最后两行是给你看的：拿到了会打印 inet addr 那一行，没拿到会打那句提示
    · 租期只有 1 小时（实测路由器给 3599~3600 秒），而 udhcpc -q 拿到就退出、
      不在后台续租 —— 板子连续开着超过 1 小时要是网自己掉了，重跑本脚本即可
    · 换热点：改 ssid / psk 两个引号里的内容；建好后 chmod +x（用 sh 跑不加也行）
    · 为什么不把它做成"开机自动跑"：板子一断电就重来，手动一句反而心里有数。
      真要做成自动，就是照这个内容写 /etc/init.d/S99wifi 再 chmod +x，
      但那样一开机就抢网卡、日志也不好看了

附录 3：给板子装根证书（重刷了根文件系统才需要做）
----------------------------------------------------------------
    症状：IP 定位正常（走 http），但"网络定位"页的地图一片空白（瓦片走 https）。
    原因：板子出厂的 /etc/ssl/certs 是空的，https 验不了证书。

    电脑上（把系统那一份证书包拆成一张张）：
        mkdir -p /tmp/ca && cd /tmp/ca && rm -f *.pem
        awk 'BEGIN{n=0} /-----BEGIN CERTIFICATE-----/{n++} n>0{print > sprintf("%04d.pem", n)}' \
            /etc/ssl/certs/ca-certificates.crt
        ls *.pem | wc -l                    # 应该是 121
        tar cf /tmp/ca.tar *.pem

    推过去装上：
        adb push /tmp/ca.tar /tmp/
        adb shell "mkdir -p /etc/ssl/certs && tar xf /tmp/ca.tar -C /etc/ssl/certs && openssl rehash /etc/ssl/certs"
        adb push /etc/ssl/certs/ca-certificates.crt /etc/ssl/cert.pem

    · 为什么不用 tar -z：板子上是 busybox 的 tar，不认 -z，压缩包解不开
    · openssl rehash 必须做：它给每张证书按内容建一个哈希名软链接（xxxxxxxx.0），
      Qt/OpenSSL 是按这个哈希名去找证书的 —— 少了这一步证书等于白装
    · 验证：adb shell "ls /etc/ssl/certs | wc -l" 应该在 240 上下
      （121 张证书 + 121 个哈希链接 + cert.pem）
